01

배경 및 문제 정의

마케팅 전략팀은 메이플스토리 M과 검은사막 모바일·아이온2·마비노기 모바일 3개 경쟁작을 대상으로 39주치 순위 데이터와 리텐션 후킹 사례를 수집해 PPT 보고서 형태로 정리해왔습니다. 이 보고서는 실제 실측 데이터(mobileindex.com), 자체 리서치, NAVER DataLab 조회 결과를 근거로 4건의 실행전략을 제안할 만큼 밀도 높은 분석을 담고 있지만, 정적 슬라이드라는 형식 자체가 세 가지 구조적 문제를 만듭니다.

  • 스냅샷 고정 — 39주 시계열이 발표 시점에 고정되어, 다음 분기 데이터가 쌓이면 전체 슬라이드를 다시 제작해야 합니다.
  • 재사용 불가한 판정 로직 — 이벤트 타이밍 압력(Low/Mid/High) 판정 로직이 텍스트 설명으로만 존재해, 신규 이벤트가 생길 때마다 사람이 수작업으로 재적용해야 합니다.
  • 출처 신뢰도가 본문에 섞임 — VERIFIED-SELF/XLSX·USER-DATALAB·UNVERIFIED-EXT 등 신뢰도가 다른 수치가 같은 슬라이드에 동일한 형식으로 표시되어, 어떤 숫자를 의사결정에 바로 써도 되는지 구분하기 어렵습니다.

본 PRD는 이 보고서의 데이터와 로직을 상시 대시보드로 옮기기 위한 요구사항을 정의합니다. 원본이 "이미 구축된 전략 시뮬레이터(대시보드 Tab4)"를 전제로 서술하고 있어, 기존 대시보드의 존재 여부는 10장 오픈이슈에서 최우선 항목으로 다룹니다.

02

목표

① 상시 갱신

분기별 보고서 재제작 없이 신규 데이터(순위·이벤트·리뷰)를 업로드하면 전체 뷰가 갱신되도록 합니다.

② 판정 로직의 도구화

이벤트 타이밍 압력 판정을 재사용 가능한 규칙으로 코드화해, 신규 이벤트 발생 시 즉시 등급을 확인할 수 있게 합니다.

③ 신뢰도 표시 기본값화

모든 수치·차트에 출처 신뢰도 라벨을 항상 노출해, 확정 수치와 참고용 추정치를 한눈에 구분합니다.

03

사용자 & 범위

대상 사용자

  • 마케팅 전략팀 — 분기 벤치마킹 리포트를 작성하고, 이벤트 캘린더 충돌을 상시 점검합니다. (주 사용자)
  • 그로스/데이터팀 — 원천 데이터(xlsx·크롤링 결과)를 대시보드에 반영하고 신뢰도 라벨을 관리합니다.
  • 경영진/의사결정자 — Executive Summary 탭 위주로 분기 성과와 실행전략 진행 상황을 확인합니다.

범위

In scope

원본 PPT의 5개 섹션(Executive Summary·경쟁사 순위·리텐션 후킹·이벤트 압력·실행전략)을 5개 탭으로 구현. 데이터는 1차로 CSV/XLSX 수동 업로드 기반.

Out of scope (1차)

mobileindex.com·NAVER DataLab 등 외부 소스의 실시간 API 자동 수집, SSO/권한 관리, 모바일 반응형 최적화는 1차 범위에서 제외하고 이후 단계로 이연합니다.

  • RETN-2케이스 스터디 3종(IP콜라보 조회수 69배 격차, 아이온2 상시복귀지원 단독사례, 성장지원형 비교)을 드릴다운 카드로 제공한다.
  • RETN-3커뮤니티 '복귀' 언급률을 4사 막대차트로 표시하되, 표본 크기·기간이 상이함을 차트 하단 각주로 항상 노출한다.
  • RETN-4출시 후 검색 관심 잔존율(M0/M1/M3/M6/M8)을 코호트 라인차트로 제공하고, 자사 피크 대비 정규화 여부를 토글할 수 있게 한다.
  • RETN-5스토어 평점·리뷰 수 비교 테이블을 제공하고, 리뷰 수가 적은 항목(아이온2·마비노기)에는 통계적 불안정성 경고 배지를 붙인다.
  • RETN-6RETN-1~5 데이터를 근거로 자사 강점/공백 요약 카드를 자동 생성한다.

Tab 3 · 이벤트 타이밍 압력 시뮬레이터

  • SIM-1자사 이벤트 캘린더를 입력·조회할 수 있는 UI를 제공한다.
  • SIM-24사 경쟁사 이벤트 캘린더를 트래킹한다 (1차는 수동 입력, 이후 자동수집 검토).
  • SIM-3자사 이벤트 기간과 겹치는 경쟁사 이벤트의 수·규모를 기준으로 Low/Mid/High 압력 등급을 자동 산정한다.
  • SIM-4등급별 대응 가이드(High: 날짜조정/카드보강 · Mid: 모니터링강화 · Low: 예정대로 진행)를 함께 노출한다.
  • SIM-5원본 보고서의 실측 사례(Case 1–5 등)를 판정 기준 학습용 참고 라이브러리로 제공한다.
⚠️ 원본 자료는 "이미 구축된 전략 시뮬레이터(대시보드 Tab4)"의 존재를 전제로 서술합니다. 신규 개발과 기존 도구 연동 중 무엇을 택할지는 10장 오픈이슈 OQ-1 확인 후 확정합니다.

Tab 4 · 실행전략 & 로드맵

  • STRAT-14대 실행전략(IP·브랜드 콜라보 확대 / 상시 복귀지원 시스템 신설 / 시스템 리마스터 검토 / 이벤트 타이밍 관리체계) 카드를 근거·실행단계·리스크·성공지표 구조로 표시한다.
  • STRAT-2난이도×효과 2×2 매트릭스에 4개 전략을 배치해 우선순위를 시각화한다.
  • STRAT-3단기(1개월)·중기(1분기)·장기(반기)·중장기(1년+) 로드맵 타임라인을 실행항목·성공지표와 연결해 표시한다.
  • STRAT-4리스크 로그(실행 리소스 분산 / 성공지표의 간접성 / 데이터 갱신 주기)를 상시 노출한다.

비기능 요구사항 & 성공지표

비기능 요구사항

  • 성능 — 39주 × 4사 × 2지표 라인차트 렌더링 1초 이내.
  • 접근성 — 카테고리 색상은 색약 검증된 팔레트를 사용하고, 모든 차트에 표 형태 대체 뷰를 제공한다.
  • 테마 — 라이트/다크 모드를 모두 지원한다.
  • 배포 — 1차는 사내 링크 공유 기반 정적 배포로 시작하고, SSO 연동은 이후 단계로 이연한다.
  • 데이터 반입 — 1차는 CSV/XLSX 수동 업로드, 이후 mobileindex.com·NAVER DataLab 자동 수집은 라이선스 확인 후 검토한다.

오픈 이슈, 가정 & 리스크

오픈 이슈

  • HIGH · OQ-1
    기존 "대시보드 Tab4" 시뮬레이터의 존재 여부

    원본 자료가 이미 구축된 전략 시뮬레이터를 전제로 서술합니다. 실제로 존재한다면 Tab3(SIM)은 신규 개발이 아니라 연동/이관으로 범위가 바뀝니다. 착수 전 확인이 최우선입니다.

  • MID · OQ-2
    데이터 신뢰도 4단계 체계의 4번째 등급 정의

    원문은 "4단계"라 언급하지만 VERIFIED-SELF/XLSX·USER-DATALAB·UNVERIFIED-EXT 3개 라벨만 확인됩니다. §04 체계를 확정하기 전 원저자 확인이 필요합니다.

  • MID · OQ-3
    결측치 처리 방식 승계 여부

    원본은 결측 구간을 200위로 대체 처리했습니다. 대시보드에서도 동일 규칙을 적용할지, "데이터없음"으로 명시 표기할지 결정이 필요합니다.

  • LOW · OQ-4
    외부 데이터 출처 재게시 가능 여부

    mobileindex.com, NAVER DataLab 등 데이터를 사내 대시보드에 재구성해 게시하는 것이 이용약관상 가능한지 확인이 필요합니다.

실행 리소스 분산

원본 전략 4건을 동시 착수하면 리소스가 분산됩니다. §09 로드맵 순서(모니터링→타이밍관리→복귀지원→콜라보/리마스터)를 그대로 따릅니다.

성공지표의 간접성

데이터 갱신 주기

커뮤니티·검색 데이터는 표본 기간이 짧은 스냅샷 성격이라 분기 단위 재수집·재검증이 필요합니다.
